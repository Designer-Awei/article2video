# 文稿 → 动画视频（分阶段、逐级确认）

用户给一份文案初稿，按下面 5 个阶段推进。**每个阶段末尾都停下来等用户确认**：没定风格不写细分镜，静帧没过不开全量渲染。用户中途提出修改，就在当前阶段改完，再请他确认一次。用户明确说“改完直接渲染合成压缩”时，可以一条流水线跑到交付，不必再停。

## 默认值（用户没说就按这个来）
- 音频：**不做配音、不加 BGM 和音效，输出带字幕的默片**，成片里没有音轨。同时导出 `subs.srt` 和 `timeline.csv`，方便之后人工配音。
- 字幕：**90px，距底边 40px**，单行，烧录在画面里。按像素宽度自动断句，规则见“技术要点”。
- 帧率 24fps，H.264 yuv420p。
- 画幅：16:9 用 1920×1080；9:16 用 1080×1920。竖屏要避开平台 UI，顶部约 12%、底部约 20% 不放关键内容，字幕每行最多约 10 个汉字。
- 每次出成片，同时出一个压缩版（CRF 24、faststart），方便直接发送。
- **画面稳定**：背景和镜头完全静止，只有元素在动。不做全局推拉、跟随，也不做背景纹理漂移，用户会觉得画面在抖。
- 版式：右上角放章节标题，Oleo 数字约 52px 加衬线章节名约 40px，做成胶囊样式；**不放左上角的斜体小字、各镜头字体不一致的小标签**，也不放顶部进度条。
- 背景：纯色牛皮纸底（如 `#EDC870`）加颗粒，不加射线；底部保留字幕地面色带和一条虚线。整个舞台缩放约 0.94，保证所有内容离虚线至少 40px。
- 字幕**不带任何标点**：句内标点换成全角空格，句末标点删掉。断句保持不变，免得和已录的配音错位。

## 阶段 1：读稿 → 判断用途和比例 → 粗分镜 → 素材清单
1. 读文稿，docx 用 python-docx。确认三件事：**用途**（科普 / 商单 / 产品发布 / 教程 / 其他）、**比例**（16:9 / 9:16 / 1:1）、**目标时长**。缺哪项就用一次 AskUserQuestion 一并问清。
2. 粗分镜：先拆章节，再按“一个意思一个镜头”切镜头。时长按约 4.2 字/秒估算，之后可以用真实配音时长覆盖。列成表：镜号、时长、旁白、画面意图（一句话）、出场角色或品牌。
3. **素材清单**，这一步最关键，逐条列出需要用户提供的东西：
   - 文稿里提到的每个品牌或产品：官方吉祥物和 **logo**，要透明底 PNG、尽量高清、无水印。最好是一张**多动作设定图**（比如 3×3），否则全片只有一个姿势会显得单调。
   - 片中出现的人物：最好用用户自己画的多动作角色设定图。
   - 结尾互动素材，比如三连动画（视频或 GIF）。
   - 截图、数据、需要核实的事实（日期、金额、产品功能），在表里标「⚠核实」。
   - 字体、品牌色等硬性要求。
4. 把粗分镜表和素材清单写在回复里，然后停下，等用户补素材、确认用途和比例。

## 阶段 2：四版风格
1. 风格库参考 `alchaincyf/huashu-art-motion`（风格配方、动画语法）和 `lemomo-ai/lemo-opuscar`（`styles/*/STYLE.md`、styleboard），用 git clone 拉下来，GitHub 一般能连。从中挑 **4 个差异明显、又适合这个用途的方向**。科普片可以选：半调案卷、50 年代教育片、瑞士排版、2026 扁平颗粒；商单偏向产品质感和品牌色。
2. 每个方向都用**同样两个镜头**出样帧：一个开场钩子，一个信息密集的正文镜头，这样四版能横向比较。做法：写一个 HTML，用 Playwright 截图，拼成一张对比图发给用户。
3. 字体：Google Fonts 和 npm 一般被拦。改从 GitHub 的 `google/fonts` 稀疏检出 OFL 字体（`git clone --filter=blob:none --sparse`）。中文用系统自带的 Noto Sans/Serif CJK SC。
4. 停下，等用户选。用户说“开场这张满意”这类话时，要确认他指的是哪一版。

## 阶段 3：细分镜 + 静帧预览
前提：风格已定，素材到齐。还缺的素材标出来，先用占位。
1. **素材处理：用原图，只抠图，不重绘**。
   - 抠图：flood-fill 去背景，加轻微 alpha 羽化。设定图先按网格切成单个动作（遇到局部变形就按区域手动切），连通域只保留大块。App 图标类素材，如果图标里有白色元素，改用圆角矩形蒙版抠。
   - **黑底视频或 GIF 素材**，比如三连动画：先把所有帧拉出来看完整时间线，有的视频前后包含两个版本（例如前 3 秒蓝色、后 3 秒粉色），要确认用哪一段。抠黑底时只把接近黑色的部分变透明（alpha = 最大通道值/100），不要按亮度整体去乘，否则灰色图标会变成白色。图标之间间距太大的，按发光范围把每个图标单独切出来，再紧凑地拼回去。最后做成精灵图（sprite sheet），由引擎按时间逐帧播放，播完停在最后一帧。
   - 多动作设定图里各个动作挨得很近时，**按透明通道的连通域逐个切**，不要按固定网格切，否则下一行的头发会被切掉。切完把九个动作排成一行检查头顶和手是否完整。
   - 简单的像素角色，比如 Claude 小螃蟹，可以按像素把身体、左右手、四条腿拆成图层（像素本身不改），这样能做手脚摆动。
   - **不擦水印、不重画、不照着参考图仿画**官方或第三方的角色。素材有水印或分辨率太低，就请用户换图。用户发来的如果是图库里别人的作品，只借鉴画风，自己原创绘制。外链（百度网盘、X 等）打不开，就请用户直接发文件。
   - 角色分工：文案提到哪家，画面就用那家的形象。**同一画面出现多家时，每个形象都配名字牌**，不要让 A 家的吉祥物站在 B 家名字旁边。通用的“AI 助手”和过场空镜，统一用用户指定的一个全局角色。
   - 多动作角色按剧情选姿势：挥手、指向、托腮、合手、看书、拿电脑等，各自对应自己的那句旁白。
   - 聊天气泡等元素要完整落在手机屏幕内；道具可以放进卡片内部（这不算遮挡），但不能跨卡片边框。
   - logo 放在对应卡片**内部**，比如卡片右上角，不要伸出卡片外。
2. 细分镜：每个镜头写清旁白、画面元素、**每个元素由哪个旁白关键词触发出场**、角色用哪个动作、转场方式。
3. 搭一个时间驱动的渲染引擎（见“技术要点”），把所有镜头写成场景代码。
4. 出静帧：每个镜头取时长 93% 处出一张，每 9 张或 16 张拼成一张对比图发给用户。同时跑**自动质检**：
   - 画面文字和同镜头的字幕不能重复。画面写要点，字幕写原话，两者互补。
   - 元素不能压到章节标题；标题尺寸改过后，检测区域要跟着更新。元素也不能进入字幕区。
   - 文字不能被别的元素压住，道具、logo 不能超出所在卡片。
   - 卡片里的文字不小于 30px，画面不能偏空。左右之间留了大片空白时，用连线、放大镜、标签这类元素衔接。
   - 元素不能出画，离边缘至少 60px。
   - 字幕里不能漏出原稿的符号，比如【】。
   - **每个镜头第一个可见元素要在 1 秒内出场**，否则开头只有字幕。删除元素（比如小标题）后必须重新检查这一项。
   - 除了 93% 处的静帧，还要抽查 t=1s 的画面和镜头之间的转场帧。
5. 停下，等用户逐张反馈。修改后**只重出改过的静帧**。

## 配音对齐（用户给了配音 SRT 时）
1. 先核对：用户 SRT 的条数和文字，应与当前字幕切分逐条一致（只允许【】这类符号差异）。对不上就停下来问。
2. 每镜时长：切点放在相邻两句配音停顿的正中间，对齐到帧。无旁白镜头（片名、章节卡、片尾）保持原时长，并记录「在配音时间轴的哪一点插入多长静音」。
3. 镜内字幕直接用 SRT 的时间；元素卡点也改用配音时间：旁白每个字按所在字幕条的起止线性插值，得到「字→时刻」表，交给引擎。
4. 写死绝对时间的动画（如跳跃关键帧），改成锚定到某个旁白关键词，在 build 阶段平移。
5. 用户的配音通常是一整条连续音轨，中间没给章节卡留空。交付时附一份插静音表和一个 ffmpeg 合成脚本（切段、插入 anullsrc、拼接、补齐总长、合进视频），用户可以自己合成。

## 阶段 4：全量渲染
1. 逐帧截图，通过管道送进 ffmpeg，每个镜头编码成 `seg/ID.mp4`。开两个进程，按时长均分镜头。
2. 每段**前后各多渲 0.3 秒**，用来做转场。合成时，在镜头边界做 0.6 秒的 xfade：普通镜头用 smoothleft，离开章节卡用 circleopen，同一画面拆开的两镜直接硬切。总时长和字幕时间轴不变。
3. **章节开头转场**不要用简陋的擦除。先给用户出 4 种样式的四宫格对比片（光圈开合 / 斜条推进 / 色块扩散 / 50 年代胶片倒计时）让他选。做法：在章节卡页面最上层叠一个覆盖层，底图是上一镜最后一帧的截图，进章节卡这一刀用硬切；章节卡元素的出场整体往后推，避开转场时间（胶片倒计时约 1 秒，章节卡相应加长到约 3.3 秒）。
4. 渲染按内容哈希增量进行，只重渲改过的镜头。**引擎代码会内联进每个镜头的 HTML**，所以改引擎等于所有镜头都要重渲。能写进单个镜头数据或 build 阶段的修复，就不要改引擎。
5. 用一个 `pipeline.sh` 跑完整流程：增量渲染 → 合成 → 压缩 → 导出 SRT。**不要用“后台 while pgrep -f 等待”的方式串联任务**：pgrep 会匹配到自己所在 shell 的命令行，导致一直等下去。启动新流水线前，先停掉旧任务。
6. 交付前检查：用 ffprobe 看时长、分辨率、音轨；逐段核对时长和时间线是否一致；均匀抽 12 帧拼成一张图过一遍，必须包含片尾。
7. 交付内容：成片压缩版、`subs.srt`、`timeline.csv`、README。用户要配乐时，再附 BGM 和音效分轨，响度 -14 LUFS / -1 dBTP，BGM 垫乐 -26 LUFS。
8. 用户要备份时，打一个 zip：源码、抠好的素材和原图、字体、文稿和分镜、风格探索、样帧，再加 README（目录、运行方法、环境版本）和 setup.sh。打完包解压到一个干净目录验证一遍。

## 阶段 5：迭代
用户会按时间点指出问题。把时间点换算成镜号（按 timeline 累加时长），只改并重渲这些镜头，再合成。

## 结尾动画（可选，用户提到“转场结尾”时做）
- 单独做一个结尾镜头 E01，约 6 秒，**不带字幕、章节标题、进度条和地面**，只留干净的纯色背景。
- 和上一镜之间直接硬切，上一镜的元素在 0.25 秒内淡出，保证画面连贯。
- 全局角色从右下角分三跳跳到画面左侧，边跳边放大到约 2 倍。用弹簧效果：起跳前压扁蓄力，空中拉长，落地后衰减回弹。空中手臂上扬、腿收起，落地后手轻摆、腿交替踏步。
- 互动动画（比如三连）从右侧滑入后开始播放，播完停在最后一帧。最后 0.8 秒淡出。

## 技术要点（踩过的坑）
- **画面是时间的纯函数**：页面实现 `INIT(cfg)` / `seek(t)`，不用 CSS transition，也不用随机状态，任意一帧都能复现。
- **按旁白关键词卡点**：元素写 `data-w="关键词"`，出场时刻 = 0.4 + 关键词在旁白中的位置 / 旁白总长 × 可用时长。没写关键词的元素，在相邻元素之间插值。同一布局拆成两镜时，用 `pre` 标出前一镜已经出过的元素，用 `hide` 标出留给后一镜的元素。另外支持 `data-at`（固定出场时刻）、`data-oat`（固定淡出时刻）、`data-pre`（一开始就在画面上）、`data-kf`（关键帧位移和缩放，可带跳跃弧线）。
- **入场用闭式弹簧公式**：普通元素 w15 / z.72，弹出类 w18 / z.45，印章 w24 / z.8。
- **别做成 PPT**：镜头之间用 xfade 推移，不要“淡出 → 白屏 → 淡入”。镜头内部靠元素按旁白卡点出场来制造节奏，不加镜头运动。
- **角色动作要克制**：只在入场后约 1.7 秒内，以及文案再次提到它时动一下，其余时间静止，不要全程弹跳。
- **字幕断行**：按像素宽度估算（汉字 89px、大写字母 60px、数字 52px），每行上限约 1730px，竖屏另算。断点优先选标点，其次选虚词前后；不在英文单词中间断开；去掉行尾标点和【】。
- **描边风格**：对每个顶层图形元素分别画一遍错位填充和描边，不要整组一起描，否则会互相压线。五官等细节跳过描边。
- **网络**：沙箱通常只能连 GitHub 和部分包管理源，edge-tts、Google Fonts、X、网盘、npm/pypi 都可能被拦。被拒就直接说明，不要绕路，请用户直接发文件。
- **容器可能重启**：后台渲染会被打断，靠哈希增量可以接着跑。长任务都放后台，定期报告进度。

## 沟通
- 每个阶段的产出，拼成对比图发给用户，再用一句话说明这一阶段需要他决定什么。版式类的改动（比如小标题样式）先出 2 个方案让用户选。
- 用户没要求就不加音频。交付时提醒片中有哪些事实待核实。
